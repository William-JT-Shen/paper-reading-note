# 02　批判性评估：作者局限、进一步局限与有效性威胁

> 目标：先准确复述作者自己承认的局限，再给出作者没有说的进一步局限。
> 本 Skill 不对论文做 8 维评分，也不给置信度等级；只写可核对的具体判断。

## 一、两类局限，先分清

| 类型 | 定义 | 来源 | 写法 |
|------|------|------|------|
| **作者承认的局限** | 作者在文中明确承认的不足、边界、失效条件或未来工作 | Discussion / Conclusion / Limitation / 假设段 / 附录脚注 | 先逐条复述，保留作者原意，标定位 |
| **进一步局限** | 作者没有承认、但从证据/设计/假设/外部有效性/可复现性可以指出的问题 | 我的分析 | 每条给证据、影响与验证方式 |

**顺序不能反**：先复述作者，再写自己的补充。把作者已经写过的 limitation 当成"我的批判"是无效的。

**三条原则**
1. 每条局限带定位（`[§4]`、`[p.24]`、`[Table 3]`），不只写形容词。
2. 区分"缺陷"与"合理取舍"：受当时数据/算力限制的简化，不必然算缺陷。
3. 不把"没做 X"当局限，除非 X 是该领域的标准做法或结论必需。

## 二、找作者承认的局限

按以下位置逐项扫：

- **Discussion / Conclusion**：`limitation`、`future work`、`we do not`、`cannot`、`remains`。
- **假设段**：作者声明假设时往往同时写明"若失效会怎样"。
- **实验设置**：作者自己注明"只在 X 设置下验证"、"Y 未测"。
- **附录 / 脚注**：补充实验里承认的偏差、失败案例。
- **摘要 / 引言末尾**：有时用"in this setting"之类限定词。

记录成表：

| # | 作者承认的局限（转述） | 定位 | 作者如何限定/解释 |
|---|------------------------|------|-------------------|
| 1 | | `[§x]` | |

**注意**
- 只复述，不评价；作者没写的不放进这一节。
- 作者说"未来工作将做 X"时，X 的缺失算作者承认的边界，但不能夸大成"作者承认失败"。

## 三、生成进一步局限（六类）

### 3.1 证据类
- 是否报告方差、随机种子、置信区间、显著性检验？
- 是否只报均值/最好值、只报成功案例？
- 指标是否真的度量了结论（指标效度）？有没有更合适的指标被回避？

### 3.2 实验设计类
- 基线是否强、是否同预算调参、是否官方实现？
- 数据划分/预处理是否有泄漏风险？
- 消融是否覆盖关键设计，还是只删一个模块？

### 3.3 假设类
- 哪个关键假设没有被独立验证？假设失效时结论还剩多少？
- 近似/线性化/平均场/平稳性假设的误差量级是否估计？

### 3.4 外部有效性
- 只在单一数据集/领域/规模/任务上验证？
- 结论是否被外推到未测试的场景？
- 真实系统/部署约束（成本、延迟、噪声）是否考虑？

### 3.5 可复现性
- 代码、数据、划分、全部超参、种子、算力是否给出？
- 关键预处理是否只存在于代码/口头描述中？

### 3.6 表述类
- 关键概念是否有歧义或前后定义不一致？
- 结论措辞是否强于证据（"证明" vs "观察到"）？
- 术语/符号是否自造且未定义？

**每条进一步局限写成**：`现象（作者没说什么）+ 证据（哪节/哪个表）+ 影响（结论会怎样）+ 如何验证`。

示例：
> 数值证据缺少收敛性检验：每周期更新 40 次只与"更频繁"比较过一次，未报告步长减半后的阈值移动 [p.30]；
> 阈值附近对离散化最敏感，这会影响 `SI=1` 的精度。可验证方式：步长减半/加倍各跑 10 个种子，比较阈值偏移。

## 四、写作模板（第 7 节）

```text
### 7.1 作者承认的局限（复述）
| # | 作者承认的局限 | 定位 |
（只放作者写过的）

### 7.2 进一步的局限（我补充）
1. <局限>：<证据>；影响：<...>；验证：<...>
2. ...

### 7.3 优点与适用边界
- 具体优点（≥2 条，说明设计解决了什么问题）
- 适用边界（在什么条件下结论成立）

### 7.4 威胁有效性与可复现性
- 内部有效性：
- 外部有效性：
- 可复现性：

### 7.5 信息缺口
- 未报告/未核实/无法读取的内容
```

**禁止**：8 维评分表、置信度 A/B/C、"什么证据会改变判断"式评级、把作者 limitation 换个说法当成自己的。

## 五、威胁有效性（Threats to Validity）

### 5.1 内部有效性
- **数据泄漏**：预处理是否用了测试集统计量？时间序列是否打乱？特征是否含标签？
- **混淆变量**：提升是否来自其他改动（更大模型、更多数据、更长训练）？
- **选择偏差**：样本如何选取？是否剔除失败样本？
- **调参不对称**：本文与基线是否同等调参预算？
- **实现差异**：基线是否官方实现、是否被弱化？

### 5.2 外部有效性
- 只在一个数据集/领域/规模上验证？
- 超参是否对新场景敏感？换规模是否仍成立？
- 任务定义是否隐含特殊假设（离线、静态、标签充足）？

### 5.3 构念有效性
- 指标与目标是否一致（accuracy ↔ 校准/公平/鲁棒）？
- 指标是否可被"刷"（BLEU 高 ≠ 翻译好）？
- 人类评估/下游任务是否支持主指标结论？

### 5.4 结论有效性
- 结论范围是否超过实验覆盖范围？
- 相关是否被写成因果？
- "显著"是否有统计检验支撑？
- 是否存在未讨论的反例/失败模式？

## 六、可复现性清单

- [ ] 代码链接（官方仓库/匿名仓库）
- [ ] 数据来源与获取方式
- [ ] 数据划分（随机种子、比例、时间切分）
- [ ] 预处理流程
- [ ] 全部超参（含搜索范围与选择依据）
- [ ] 随机种子与重复次数
- [ ] 硬件与训练/仿真时长
- [ ] 评估脚本与指标实现
- [ ] 基线实现来源与调参设置

缺失项写入第 7.5 节"信息缺口"，不要脑补。

## 七、统计证据规则

| 情况 | 要求 |
|------|------|
| 单次运行 | 只能写"报告了一个结果"，不能写"稳定提升" |
| ≥3 种子 | 报均值 ± 标准差；比较时看方差是否重叠 |
| 显著性检验 | 记录检验类型、样本单位、p 值；配对设计用配对检验 |
| 多重比较 | 多数据集/多指标时需校正，或说明未校正 |
| 效应量 | 除 p 值外给出差值大小；小样本下 p 值不可靠 |
| 误差棒/CI | 说明是 std / sem / CI，样本数 n |
| 失败案例 | 只报成功案例的结果可信度打折 |

## 八、红旗清单（读到即记录，并尝试核实）

| 红旗 | 为什么危险 | 如何核实 |
|------|------------|----------|
| 无方差/单次运行 | 提升可能来自随机性 | 找种子数、误差棒、附录 |
| 基线明显弱/未调参 | 提升被高估 | 看基线来源、是否同预算 |
| 只在测试集上选超参 | 乐观偏差 | 看是否提到 dev set |
| 数据泄漏 | 结果不可复现 | 看预处理与划分 |
| 指标与结论不匹配 | 结论无效 | 看指标定义与任务目标 |
| 只报均值不报分布 | 掩盖长尾失败 | 找 per-task/per-domain 结果 |
| 消融只删一个模块 | 无法归因 | 看变体覆盖 |
| 所有变体都优于基线 | 可疑 | 检查实验设计/报告偏差 |
| 结论外推到未验证场景 | 过度概括 | 对照实验覆盖范围 |
| 引用自己/低质量来源过多 | 可能选择性引用 | 抽查关键引用 |

## 九、常见误判

1. **把作者 limitation 抄一遍当批判**——作者没写的才是你的价值。
2. **把"没做 X"当缺陷**——除非 X 是该领域标准做法。
3. **把"简单"当"不新"**——简洁有效的设计往往更难。
4. **把"复杂"当"好"**——堆模块不等于贡献。
5. **用引用量/顶会标签代替质量判断**——只作外部信号。
6. **只挑毛病不给可取之处**——好的批判是"在什么条件下成立/不成立"。
7. **把作者明确承认的边界再写一遍当"进一步"**——重复不增加信息。

## 十、交付前检查

- [ ] 7.1 只包含作者承认的局限，且有定位
- [ ] 7.2 至少 3 条进一步局限，每条含证据与影响
- [ ] 没有 8 维评分表、没有置信度等级
- [ ] 7.4 覆盖内部/外部有效性与可复现性
- [ ] 7.5 列出未报告/未核实的信息
- [ ] 优点具体，术语准确
