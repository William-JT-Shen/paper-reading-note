# 论文阅读笔记 / Paper Reading Note

> 目标：把一篇论文变成**可复核、可比较、可行动**的笔记，而不是一篇更长的摘要。

> 本 Skill 的 GitHub 仓库另提供[仓库总览](../README.md)与[英文版说明](../en/README.md)；安装与使用场景见仓库总览。

大多数 AI 生成的文献笔记有四种通病：改写摘要、只写结论不写方法、只夸不批、读完与自己无关。
本 Skill 用四条硬约束逐一封堵，并给出固定模板、公式详解框架、局限分析框架、自检脚本和可复制的提示词。

## 四条铁律

| # | 铁律 | 具体要求 | 对应通病 |
|---|------|----------|----------|
| 1 | **证据先行** | 每个关键论断后跟定位符（`[§4.2]`、`[Table 2]`、`[p.7]`）；找不到出处的写"未报告"，不猜；引用 `Eq. (x)` 时若该式尚未在笔记中出现，须在引用处写出公式 | 摘要改写 |
| 2 | **三分判断** | 把"作者声称 / 证据支持 / 我的判断"分开写，并标注 `[原文]`、`[推断]`、`[外部]`、`[疑问]` | 只夸不批 |
| 3 | **方法优先** | 方法部分细到可复现：输入输出、关键模块与公式、逐公式详解与表外推导、数据划分、超参、算力、代码/数据可得性 | 只写结论不写方法 |
| 4 | **连接自己** | 至少写 2 条与读者研究的关系（可迁移方法、可复用数据/指标、要避开的问题、下一步实验） | 读完就忘 |

**不写笔记的几种情况**：只拿到标题；只拿到摘要（→ 只能产 L1 速读卡并显著标注）；PDF 文本层损坏且未 OCR；
用户要求"直接写篇综述"但一篇论文都没读。此时先说明限制，再降级产出，**不许补全想象内容**。

**笔记不写使用场景**：正文与 frontmatter 不出现"汇报、分享、课程作业、集体讨论"等使用场景字样，
也不写阅读目的/阅读目标；笔记只呈现论文内容、证据与研究判断。

## 何时使用

**使用**：读单篇论文 / 预印本 / 讲义；写或更新文献笔记；多篇论文对比；写文献综述笔记；
找研究空白；快速判断一篇论文是否值得精读；审查论文结论的可信度。

**触发词**：
- 中文：精读这篇论文、写文献笔记、读一下这篇、做个速读卡、对比这几篇、文献综述、找研究空白、这篇可信吗
- English: read this paper, literature note, paper summary, compare these papers, literature review, research gap, critical appraisal

**不使用**：代写论文正文或审稿意见；伪造引用、数据或实验结果；与文献无关的普通摘要请求。

## 快速开始

把下面的提示词直接交给 Agent（路径换成实际文件）：

```text
# 单篇精读（默认 L2）
读 <paper.pdf>，按 paper-reading-note 的标准流程写一篇完整的文献阅读笔记，
输出到 notes/<paper_id>.md，并用本 Skill 的 check_note.py 检查 notes/ 目录。

# 只要速读卡（L1，10 分钟）
给 <paper.pdf> 做一张速读卡，判断是否值得精读。

# L3 深度笔记（公式详解 + Python 复现）
读 <paper.pdf>，按 L3 写：第 4.3 节逐公式解释含义与思想来源，
第 7 节先复述作者局限再补进一步局限，第 11 节给出可运行的 Python 复现代码，第 12 节核查推导。

# 多篇对比 + 综述
把 notes/ 下这 6 篇关于 X 的论文做成对比矩阵，再写一篇综述笔记：
共性、分歧、趋势、研究空白，每条结论标注来自哪几篇。

# 更新已有笔记
读 notes/xxx.md，补充第 5 节"失败案例"和第 9 节"研究空白"，保留我原有的判断和日期。
```

## 输入能力边界（重要）

| 输入 | 可产出 | 处理方式 |
|------|--------|----------|
| PDF（有文本层） | L1 / L2 / L3 | 文本层优先；双栏按栏读；公式保留编号；图表按 Table/Fig 编号引用 |
| PDF（扫描件） | 先 OCR 再 L1/L2 | OCR 质量差时只做 L1，并列出"未能读取"的页 |
| 只有摘要 / 网页简介 | **仅 L1**（`source_scope: abstract`），标题注明"仅摘要" | 禁止写方法细节、训练设置、数值对比；自检加 `--abstract`，定位符用 `[Abstract]` |
| LaTeX / HTML 全文 | L1 / L2 / L3 | 保留 `\section` 编号、公式编号、表格标签 |
| 非英文论文 | L1 / L2 / L3 | 笔记仍用中文；关键定义/术语保留原文并标注译文 |
| 多篇论文 | 批量 L1/L2 + 对比矩阵 + 综述 | 先建 `notes/index.md`，再逐篇，最后矩阵/综述 |
| 已有笔记 | 增量更新 | 保留原判断与日期，新增内容标"更新于 YYYY-MM-DD" |

**版本规则**：预印本必须记录版本（如 v1/v7）与访问日期；同一论文不同版本的方法/数值可能不同，更新时不要覆盖旧版结论，注明"v7 与 v1 的差异"。

## 阅读深度：L1 / L2 / L3

| 级别 | 名称 | 建议用时 | 产出长度 | 必填章节 | 证据下限 |
|------|------|----------|----------|----------|----------|
| L1 | 速读卡 | 10–15 分钟 | 300–600 字 | 0,1,2,4,5,7 | ≥3 个定位符，第 5 节 ≥2 个数值 |
| L2 | 标准笔记（默认） | 45–90 分钟 | 1200–3500 字 | 0–9 | ≥8 个定位符，第 5 节 ≥4 个数值 |
| L3 | 深度笔记 | 2–4 小时 | 3000–6000 字 | 0–12（追加复现计划与公式核查） | ≥15 个定位符，第 5 节 ≥6 个数值 |

> **仅摘要**：L1 例外——定位符 ≥1（`[Abstract]`）、第 5 节数值 ≥1，可删消融/成本行；自检加 `--abstract`。
> 数值按“小数或百分号、去重”计；重复同一个定位符不计数。
> **公式详解**：L2/L3 第 4 节必须含 `### 4.3 公式详解`：先写 `4.3.0 推导主线`（公式如何串联、每步为什么引入下一式），再逐条写公式含义、符号、推导动机、思想来源、作用、假设。每个公式表格下方（表格外）写"推导过程"：从推导动机/思想来源出发，分步到目标公式，关键式独立成式并标原编号；有推导时表格的"推导动机/思想来源"两行可精简成一句话。
> **L3 复现**：第 11 节“复现计划”必须含可运行的 Python 代码；第 12 节为“公式与推导核查”。

**自动选级**：用户未说明时默认 L2；用户说"快速看看/帮我筛一下/值不值得读"→ L1；用户说"要复现/要写进论文/
要深入公式"→ L3；只拿到摘要 → 强制 L1，并在 frontmatter 设 `source_scope: abstract`（自检加 `--abstract`）。

## 工作流（默认 L2）

### Step 0　立卡（2 分钟）

1. 生成 `paper_id`：`<第一作者姓><年份>-<3–5 个词的主题 slug>`，全小写，例：`vaswani2017-attention`。
2. 记录：文件路径、来源（期刊/会议/arXiv/网页）、版本与访问日期、页数。
3. 阅读目的只用于**内部**决定重点，不写进笔记：
   - 存档 → 方法与主结果完整，局限与讨论优先；
   - 选题/找 gap → 相关工作、局限、未来工作优先，必须多篇对比；
   - 复现 → 超参、数据划分、代码/数据链接、算力优先，进入 L3。
4. 目的或输出语言不清楚时**最多问一次**：输出中文还是英文？没回复就按默认（L2、中文、Markdown）继续，不阻塞。

### Step 1　结构扫描（5–10 分钟）

只读六处：标题、摘要、引言最后一段（贡献列表）、所有图表标题、结论、附录标题。

产出"主线三句"（每句 ≤25 字）：

- **问题**：它要解决什么？在什么设定下？
- **做法**：核心机制是什么（不是模型名）？
- **结果**：关键数值是多少（没有数值就写"未报告"）？

同时列出：必读章节（方法核心、主结果表、消融、limitation）、图表清单、有明显疑点的位置。
**篇幅大时**：优先读摘要、引言末尾、方法、主结果表、结论；相关工作与附录按需；在笔记里记录跳过的章节。
**若主线三句写不出来，说明还没读懂，只能停在 L1 并说明原因。**

### Step 2　元数据抽取

按 `references/01-extraction-prompts.md` 的 Schema 抽取：标题、作者、机构、年份、发表处、DOI/URL、
关键词、代码/数据链接、论文类型（实证/理论/综述/系统）。输出为 YAML frontmatter（见"输出契约"）。

### Step 3　四张抽取表（阅读的核心工作量）

按顺序填四张表，除"我的判断"外，表内每一行都要有定位符：

1. **问题表**：输入/输出定义、假设、约束、失败模式、与已有定义的区别。
2. **方法表**：整体架构、关键模块与公式、公式之间的串联/推导主线、逐公式的含义/符号/动机/思想来源/作用、损失函数、训练流程、超参、复杂度、实现细节、可复现性。
3. **证据表**：数据集（规模/划分/预处理）、基线（是否强基线/同设置）、指标（定义/方向）、主结果、
   消融、显著性/方差、失败案例、计算成本。
4. **结论表**：三列——作者声称 / 证据支持到什么程度 / 我的判断。

每张表的必答问题、判"够了"的标准和"糊弄信号"见 `references/01-extraction-prompts.md`。
**不允许跳过第 3 张表直接写结论**——这是笔记可信度的来源。四张表是工作底稿：可精简后放附录，或删除；
正文按模板重写，不要把表格原样堆进笔记。

### Step 4　批判性评估

使用 `references/02-critical-appraisal.md` 的框架，**不评分、不给置信度**，按顺序写清：

- **7.1 作者承认的局限（复述）**：作者在 limitation/discussion/假设/未来工作中明确承认的不足，
  逐条转述并标定位；作者没写的不放进这一节。
- **7.2 进一步的局限（我补充）**：至少 3 条作者没有承认的局限，每条写"现象 + 证据 + 影响 + 如何验证"；
  不得重复 7.1 已复述的内容。
- **7.3 优点与适用边界**：至少 2 条具体优点（说明哪个设计解决了什么问题），并写结论在什么条件下成立。
- **7.4 威胁有效性与可复现性**：内/外部有效性、指标效度、缺失基线/消融、代码/数据/种子。
- **7.5 信息缺口**：未报告、未核实、无法读取的内容。

### Step 5　定位（与最接近的工作比较）

找出 2–4 篇最接近的工作：直接前作、同期竞争、后续改进。优先用论文的相关工作与参考文献列表；
能联网再核查引用关系；不能联网就在笔记里标"引用链未核查"，**不编造引用**。用三维定位：问题同/不同、方法同/不同、结论同/不同。

### Step 6　连接与空白

回答 5 个问题（第 8 节）：可迁移的方法、可复用的数据/指标、要避开的问题、与读者研究问题的关系、
下一个可做的实验。

用四分类写研究空白（第 9 节）：**问题空白 / 方法空白 / 证据空白 / 应用空白**。每条 gap 必须包含
三要素：证据（哪几篇的哪个结果）、为什么还没解决、可验证的下一步。判定标准见
`references/03-comparison-synthesis-gap.md`。

若读者研究方向未知：写"待确认"，给出 3 个可能方向，不虚构读者背景。

### Step 7　组装、自检与落盘

1. 用 `templates/` 对应模板组装（L1 → `speed-card-L1.md`；L2 → `note-L2.md`；L3 在 L2 基础上追加
   `templates/reproduction-plan.md` 的 `## 11. 复现计划`（含可运行 Python 代码）与 `## 12. 公式与推导核查`）。
2. 逐项过"质量门"清单（见下）。
3. 运行本 Skill 的 `check_note.py` 自检：在任意工作目录执行
   `python "<skill-dir>/scripts/check_note.py" notes/`
   （`<skill-dir>` 换成本 Skill 的实际安装目录；直接传目录，脚本会检查其中所有笔记），通过后交付；失败则按报告修复。
4. 落盘命名：`notes/<paper_id>.md`；多篇模式同时更新 `notes/index.md`、`notes/matrix.md`。

## 输出契约

### 文件与命名

```text
notes/
├── index.md                     # 多篇索引（按主题/年份分组，一行一篇）
├── matrix.md                    # 对比矩阵（scripts/build_matrix.py 生成后人工补列）
├── synthesis-<topic>.md         # 主题综述笔记
└── <paper_id>.md                # 单篇笔记（L1/L2/L3 同一命名）
```

- 文件名与 frontmatter 的 `paper_id` 一致；同名冲突时加 `-v2`。
- 默认输出到当前工作区的 `notes/`；用户指定目录则从其指定。
- 默认 Markdown + YAML frontmatter（Obsidian 可直接识别为 properties）。

### YAML frontmatter 字段

| 字段 | 必填 | 示例 | 规则 |
|------|------|------|------|
| `paper_id` | 是 | `vaswani2017-attention` | 第一作者姓+年份+slug，小写连字符 |
| `title` | 是 | `Attention Is All You Need` | 原文标题，不翻译（中文标题可放括号） |
| `authors` | 是 | `[Vaswani, Shazeer, ...]` | 姓在前；>6 人可写前 3 + `et al.` |
| `affiliations` | 否 | `[Google Brain, ...]` | 第一单位优先 |
| `venue` | 是 | `NeurIPS 2017` / `arXiv:1706.03762v7` | 区分正式发表与预印本 |
| `year` | 是 | `2017` | 发表年（预印本用首次公开年） |
| `doi` / `url` | 否 | `10.48550/arXiv.1706.03762` | 有 DOI 优先 |
| `keywords` | 是 | `[Transformer, self-attention]` | 3–6 个，原文词优先 |
| `reading_level` | 是 | `L2` | `L1` / `L2` / `L3` |
| `source_scope` | 否 | `full` | `full` / `abstract`（仅摘要时必填） |
| `status` | 是 | `done` | `draft` / `done` / `revisit` |
| `created` / `updated` | 是 | `2026-10-21` | ISO 日期；更新时只改 `updated` |
| `tags` | 否 | `[NLP, attention]` | 2–5 个，便于检索 |

> 不记录阅读目的、使用场景、置信度等级；这些不进入笔记。

### 章节结构与写作要求（L2）

| # | 章节 | 必答内容 | 常见错误 |
|---|------|----------|----------|
| 导 | 领域导读 | 领域在做什么、三层问题（单个振子/成对锁定/群体阈值）、本文补哪一层；2–3 段，写给不熟悉该领域的人 | 写成摘要复述；自绘图未标"自绘，非原文" |
| 0 | 速览 | 问题 / 做法 / 结果 / 为什么重要，四条各 ≤40 字 | 写成摘要翻译；"结果"没有数值 |
| 1 | 论文信息 | 元数据表 + 代码/数据链接 + 论文类型 | 漏版本、漏代码链接 |
| 2 | 研究背景与问题定义 | 领域现状、具体痛点、形式化定义、假设、成功标准 | 大段复述引言，没有形式化 |
| 3 | 相关工作与定位 | 2–4 篇最接近工作 + 三维定位 | 罗列引用，不说差异 |
| 4 | 方法 | 架构、关键模块与公式、**4.3 公式详解**（4.3.0 推导主线 + 每式含义/符号/动机/思想来源/作用/假设 + 表外推导过程）、训练细节、复杂度、实现细节 | 只写"提出了 X 方法"；公式只抄不解释、公式之间没有串联 |

### 写作与格式

- 默认中文；术语首次出现给英文原文，之后统一用同一译名；专有名词不硬译。
- 结论先行：每段第一句是判断，后面才是证据；一段只讲一个论点。
- 优先用表格和短列表；长段落只在需要论证时出现。
- 数字与单位按原文；中文与英文/数字之间加空格（`28.4 BLEU`、`8 个 P100`）。
- 不写论文腔（"本文旨在"）、不写营销腔（"颠覆性突破"）、不写空泛评价（"效果很好"）。
- 公式用 LaTeX；符号首次出现给定义，可附符号表。
- **公式引用闭环**：引用原文的 `Eq. (x)`/附录式编号时，若该公式在笔记前文尚未出现，就在引用处写出公式（行内或独立公式均可）；范围引用（如 `Eq. (A4)–(A12)`）只保留已在笔记中展示的编号。
- **表外推导**：4.3 每个公式表格下方（表格外）写完整推导——从"推导动机/思想来源"出发，分步到目标公式；每步说明用了哪条假设/哪一式，关键一步独立成式并标原编号。有推导时表格的"推导动机/思想来源"可精简为一句话。
- **推导语体**：4.3 的"推导过程"用论文式陈述：以"设/令/由…得/于是/故/唯有"推进；假设、代入、近似、结论各自成句；关键式独立成段并标原编号。不写教学式分步编号，也不写"这一步的必要性""不构成循环论证""值得注意的是"一类元话语。
- **推导不跳步**：4.3 的"推导过程"要给出每一步所依据的原始公式，并说明做了什么操作（代入、一阶展开、周期平均、分部积分、取极限）；移项、合并同类项、两边同乘等基础代数不必逐行展开。禁止只写"由 Eq. (X) 得 Eq. (Y)"而不说明依据与操作。引用附录式（如 (A1)(A3)(A8)）时先写出该式。其他章节可概括，推导块不可。
- **起始式标注来源**：推导中给出任一初始表达式时，先说明它凭什么成立：是定义（相位/频率的定义、$M$ 的定义）、公认事实或守恒律（振子数守恒）、前文结论（写明 Eq. (x) 或 §x.x），还是论文的模型假设（线性响应、单群假设）。不要让读者猜；同一式只标一次，后文引用不必重复。
- **复合式分层给出**：起始式由几项组成时，先写最简情形（如自由运行的 $d\phi/dt=1/T$），再说明新情境下为什么多出某一项（如刺激加入后把频率增量记为 $\Delta f$，故 $d\phi/dt=1/T+\Delta f$）。不要只抛最终复合式再用括号补一句解释。
- **关键判断给机制**：遇到"唯有…才…""必然…""等价于…""只有…稳定"这类判断，不要只下结论，按四步写：① 判断本身；② 最小机制（1–3 个式子：线性化、符号分析、守恒、极限情形，只留必要步骤）；③ 一句口语直觉（把符号翻译成"推前会怎样"）；④ 边界（何时失效、哪一项只修正数值）。不写完整证明，也不只下结论；机制超过 3 个式子或直觉超过 2 句，通常已经累赘。定义与移项不在此列。线性化要写出 Taylor 展开式（一阶项 + 余项），不能只写"线性化得"；符号分析要给出不等号的来源。
- **读者标记与附录 1**：读者可能在 md 中用 `<u>术语</u>$^{[n]}$` 标出不懂的专有名词，表示希望 Agent 在附录 1 解释。看到这类标记时：① 保留标记与编号；② 在文末写 `## 附录 1：术语解释`，按编号逐条给出"一句话定义 + 在本文中的作用 + 与相邻概念的区别/常见误解"，每条 2–4 句；③ 编号与标记一一对应，错号视为未完成；④ 附录不计入正文产出长度，但不得用来装正文内容。
- **语病检查**：推导写完后逐句通读：检查主语残缺、搭配不当、成分赘余、逻辑重复（如同一个假设拆成"既…又…"）、指代不明；发现问题就地改写，不留在交付稿里。
- **公式渲染**：数学模式内不要出现中文（`\text{}` 内不放 CJK，中文写在公式外）；行间公式用多行 `$$`（`$$` 单独占行），不要写成单行 `$$...$$`；表格内用 `\lvert...\rvert` 代替裸 `|`，避免破坏表格。
- **领域导读**：L2/L3 在 `## 0. 速览` 前写 `## 导读：这个领域在做什么`（2–3 段）：领域的研究对象、三层问题（单振子如何被刺激改变相位 / 两个振子如何锁定 / 大量振子能否同步、阈值与群体频率）、本文补的是哪一层。写给不熟悉该领域的读者，只给背景，不写本文结论；可配自绘示意图，图注须标"自绘，非原文"。
- **图表嵌入**：原文图从 PDF 裁切，建议连同图注一起裁，确保坐标轴、曲线、标注完整；存到 `notes/figures/`，用相对路径引用。一图一行、居中显示（`<p align="center"><img src="..." width="620" style="background:#fff; padding:6px; border-radius:6px;"></p>`），不要多图挤在同一行；图注写"图号 + 页码 + 一句话"。自绘图与原文图分开标注，并在正文说明它辅助哪个概念。

## 证据规范（摘要）

完整规则见 `references/04-evidence-and-style.md`，最低要求：

| 需求 | 写法 | 说明 |
|------|------|------|
| 小节 | `[§4.2]` | 论文自己的编号 |
| 页码 | `[p.7]` / `[PDF p.12]` | 印刷页与物理页分开 |
| 图表 | `[Table 2]` / `[Fig. 3]` | 用论文编号 |
| 公式 | `[Eq. (1)]` | 含编号 |
| 行号 | `[L120–135]` | LaTeX 源码/文本行 |
| 版本 | `[arXiv v7, §3.1]` | 预印本必带版本 |

四类标签：`[原文]` 论文明确写了；`[推断]` 我的推理；`[外部: 来源]` 论文之外的知识（必须给来源）；
`[疑问]` 待核实。标签与定位符可连用：`28.4 BLEU [原文][Table 2]`。

**数值纪律**：原样抄录，不二次换算；注明相对/绝对提升；不同设置/指标不可直接比较；"显著"只在实际
做过统计检验时使用；未报告就写"未报告"，不推算。

## 多篇模式

1. 先给每篇做 L1 或 L2 笔记（**不允许直接拿摘要做矩阵**）。
2. 运行本 Skill 的 `build_matrix.py`：`python "<skill-dir>/scripts/build_matrix.py" notes/ -o notes/matrix.md --csv notes/matrix.csv`；
   脚本生成自动列，并留出 Delta / Evidence quality / Reproducibility / Relevance 空列，人工填写。
3. 用 `templates/synthesis.md` 写综述：问题谱系 → 方法族与共识 → 分歧及原因 → 趋势 → 空白与机会。
4. 综述中每条判断标注来源篇数与笔记链接；区分"共识（≥2 篇独立证据）/ 争议 / 单篇发现"。
5. 引用链（能力 11）与概念图（能力 7）按需加在附录，格式见 `references/03-comparison-synthesis-gap.md`。
