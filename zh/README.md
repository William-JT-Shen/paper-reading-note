# 文献阅读笔记 Skill（paper-reading-note）

[English](../en/README.md) · [仓库总览](../README.md)

把「读论文」变成「写出一份可复核、可比较、可行动的笔记」的完整技能包：固定模板 + 逐节提问清单 +
逐公式详解 + 局限分析 + 多篇对比矩阵 + 研究空白分析 + 自检脚本；L3 复现计划附带可运行的 Python 代码。

大多数 AI 生成的文献笔记有四种通病：改写摘要、只写结论不写方法、只夸不批、读完与自己无关。
本 Skill 用四条硬约束逐一封堵，并把这些约束写成可执行的检查：

1. **证据先行**：每条关键论断带章节/页码/图表/公式定位符；找不到出处写「未报告」，不猜。
2. **三分判断**：作者声称 / 证据支持 / 我的判断分开写，并标注 `[原文]`、`[推断]`、`[外部]`、`[疑问]`。
3. **方法优先**：方法细到可复现——输入输出、关键模块与公式、逐公式详解与表外推导、数据划分、超参、算力。
4. **连接自己**：至少 2 条与读者研究的关系（可迁移方法、可复用数据/指标、要避开的问题、下一步实验）。

## 功能

- **三档阅读深度**：L1 速读卡（10–15 分钟）、L2 标准笔记（45–90 分钟，默认）、L3 深度笔记（含复现计划与公式核查）。
- **固定模板**：L1/L2/L3 共用一套 `paper_id` 命名与 YAML frontmatter，Obsidian 可直接读取为 properties。
- **4.3 公式详解**：先写 4.3.0 推导主线（公式如何串联、每步为什么引入下一式），再逐式写含义、符号、
  推导动机、思想来源、作用、假设；每个公式表格下方（表格外）写完整推导。
- **批判性评估**：7.1 复述作者承认的局限，7.2 补至少 3 条作者未承认的局限（现象 + 证据 + 影响 + 如何验证）；
  不评分、不给置信度。
- **多篇模式**：批量 L1/L2 → 对比矩阵 → 五段式综述 → 研究空白四分类（问题/方法/证据/应用）。
- **证据规范**：定位符格式、四类标签、数值纪律、措辞阶梯、引用格式；区分共识、争议与单篇发现。
- **术语附录**：读者用 `<u>术语</u>$^{[n]}$` 标出不懂的名词，Agent 在「附录 1：术语解释」按编号逐条解释。
- **可执行质量门**：`check_note.py` 检查必填章节、定位符数量、第 5 节结果数值、4.3 公式详解与表外推导、
  7.1/7.2 局限结构、L3 复现代码与占位符残留；`build_matrix.py` 从笔记生成矩阵 Markdown + CSV。

- **公众号封面（可选）**：深蓝 + 金色相位圆，主封面 900×383、方封面 600×600；细则见 `references/06-cover-style.md`。

## 安装

克隆仓库后任选一种方式。下文 `<skill-dir>` 指本仓库的 `zh/` 目录：

```bash
git clone <repo-url> paper-reading-note
cd paper-reading-note
```

### Claude Code（个人技能）

```bash
mkdir -p ~/.claude/skills
cp -r zh ~/.claude/skills/paper-reading-note-zh
```

Windows PowerShell：

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\.claude\skills" | Out-Null
Copy-Item -Recurse zh "$env:USERPROFILE\.claude\skills\paper-reading-note-zh"
```

### Claude Code（项目技能）

```bash
mkdir -p .claude/skills
cp -r <path-to>/zh .claude/skills/paper-reading-note-zh
```

### Codex / DSH / OpenCode 等

把 `zh/` 放进对应工具的技能目录；或直接把 `<skill-dir>/SKILL.md` 的路径交给 Agent，
让它先读技能再开始读论文。

### 不安装

在对话里直接说：

```text
按 <skill-dir>/SKILL.md 的流程读这篇论文。
```

## 快速开始

把提示词直接交给 Agent（`<paper.pdf>` 换成实际文件路径，`<skill-dir>` 换成 `zh/` 的实际路径）：

```text
# L2 标准笔记（最常用）
读 <paper.pdf>，按 paper-reading-note 的 L2 流程写阅读笔记，输出到 notes/<paper_id>.md。
写完运行 python "<skill-dir>/scripts/check_note.py" notes/ --strict 检查。

# L1 速读卡（10–15 分钟，判断是否值得精读）
给 <paper.pdf> 做一张 L1 速读卡，只回答：问题、做法、关键结果、是否值得精读。

# L3 深度笔记（公式详解 + Python 复现）
读 <paper.pdf>，按 L3 写：第 4.3 节逐公式解释含义与思想来源，
第 7 节先复述作者局限再补进一步局限，第 11 节给出可运行的 Python 复现代码，第 12 节核查推导。

# 多篇对比 + 综述
把 notes/ 下这 6 篇关于 X 的论文做成对比矩阵，再写综述：
问题谱系、方法族与共识、分歧及原因、趋势、研究空白。
每条判断标注来自哪几篇。
```

## 自检与矩阵

```bash
# <skill-dir> = 本仓库 zh/ 目录的绝对路径；可在任意工作目录执行
python "<skill-dir>/scripts/check_note.py" notes/                    # 检查目录下所有笔记
python "<skill-dir>/scripts/check_note.py" notes/ --strict           # 警告也视为失败
python "<skill-dir>/scripts/check_note.py" notes/ --abstract         # 仅摘要卡模式
python "<skill-dir>/scripts/build_matrix.py" notes/ -o notes/matrix.md --csv notes/matrix.csv
```

- 直接传目录：PowerShell 不会展开 `notes/*.md`；脚本会递归查找并跳过 `index.md`、`matrix.md`、
  `README.md` 与模板文件。
- `--strict` 用于交付前自检，也可直接放进 CI。
- `check_note.py` 退出码：`0` 通过；`1` 检查未通过（或 `--strict` 下存在警告）；
  `2` 路径/参数错误（含目录中没有可检查的笔记）。
- `build_matrix.py` 退出码：`0` 成功；`1` 没有可用笔记；`2` 路径错误。脚本生成自动列，
  并留出 Delta / Evidence quality / Reproducibility / Relevance 四个空列供人工填写。
- 两个脚本只依赖 Python 标准库（Python 3.9+）。

示例笔记可以直接验证：

```bash
python "<skill-dir>/scripts/check_note.py" "<skill-dir>/examples" --strict
```

## 输出结构

L2 标准笔记包含：

| 章节 | 内容 |
|------|------|
| 导读 | 领域在做什么、三层问题、本文补哪一层 |
| 0 速览 | 问题 / 做法 / 结果 / 为什么重要 |
| 1 论文信息 | 作者、发表处、版本、代码/数据 |
| 2 问题定义 | 背景、痛点、形式化、假设、成功标准 |
| 3 相关工作 | 最接近的 2–4 篇 + 三维定位 |
| 4 方法 | 架构、关键模块与公式、4.3 公式详解、训练细节、复杂度 |
| 5 实验与证据 | 数据、基线、主结果、消融、失败案例、统计 |
| 6 主要发现 | 作者声称 / 证据支持 / 我的判断 三列 |
| 7 批判性评估 | 7.1 作者局限复述、7.2 进一步局限、7.3 优点与边界、7.4 威胁有效性、7.5 信息缺口 |
| 8 启发 | 可迁移、可复用、要避开、下一步实验、可追问问题 |
| 9 研究空白 | 问题/方法/证据/应用四类，每条含证据与可验证下一步 |
| 10 关键原文摘录 | 逐字引用 + 页码 |
| 附录 1 | 术语解释（按读者标记的编号逐条解释） |

L3 追加：

| 章节 | 内容 |
|------|------|
| 11 复现计划 | 环境、参数表、可运行的 Python 代码、运行命令、验收标准、证伪条件、已知缺口 |
| 12 公式与推导核查 | 符号/量纲表、逐步核对、勘误记录、遗留疑点 |

## 设计说明

- **一个 Skill 而不是多个小技能**：元数据抽取、方法抽取、批判性评估、对比矩阵、综述与空白分析
  等能力被编排进 7 步工作流；多篇模式复用同一套笔记，避免小技能互相不知道对方存在。
- **三档深度**：L1 速读卡 → L2 标准笔记 → L3 深度笔记，按「值不值得读」逐步升级。
- **反幻觉优先**：每条结论要定位符；四类标签区分原文/推断/外部/疑问；只有摘要时强制降级 L1。
- **公式详解有主线**：4.3 先写 4.3.0 推导主线（从哪出发、每步为什么引入、下一式接什么），
  再逐式解释含义/符号/动机/来源。
- **公式引用闭环**：引用原文 `Eq. (x)`/附录式编号时，若该式在笔记中尚未出现，就在引用处写出公式；
  范围引用只保留已展示的编号。
- **表外推导**：4.3 每个公式表格下方写从「推导动机/思想来源」到目标公式的完整推导。
- **推导不跳步**：给出所依据的原始公式与操作说明（代入/展开/平均/积分）；移项等基础代数不必展开。
- **起始式标注来源**：定义、公认事实/守恒律、前文结论（Eq. x）或论文假设；复合式先给最简情形，
  再说明新增项。
- **关键判断给机制**：「唯有/必然/等价」类判断写「判断 → 1–3 式最小机制 → 一句直觉 → 边界」；
  线性化写出 Taylor 展开。
- **语病检查**：推导写完后逐句通读，检查主语、搭配、赘余、逻辑重复与指代。
- **领域导读**：L2/L3 在 §0 前加 2–3 段领域介绍（研究对象、三层问题、本文补哪一层），
  可配自绘示意图，图注标「自绘，非原文」。
- **图表嵌入**：原文图从 PDF 裁切（连图注、保完整），存 `notes/figures/`；一图一行、居中，
  图注带图号与页码。
- **读者标记与附录 1**：术语标记与附录条目编号一一对应；附录不计入正文长度。
- **批判性评估不评分**：不设 8 维评分、不给置信度；先复述作者承认的局限，再补进一步局限。
- **可执行的质量门**：把「笔记写得好不好」变成 `check_note.py` 可自动验证的清单。
